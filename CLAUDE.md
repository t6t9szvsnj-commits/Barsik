# Заметки для работы над проектом

## Что это

Ассистент для уборки рабочего стола на macOS. Две версии, общий движок.

```
versions/              все три версии в одной папке
  desktop_assistant.py   версия 1: окно + движок (вся логика работы с файлами)
  desktop_cat.py         версия 2: кошка на рабочем столе, импортирует движок
  desktop_barsik.py       версия 3: Барсик (3D-кадры), наследует мозг и окна версии 2
  sprites/barsik/          кадры Барсика + meta.json (якорь, рот, макушка, шаг в пикселях)
                         и гортензия: flower_carry/gift.png + flower.json
tools/3d/v3_cat.py     модель Барсика в Blender; `-- sprites <папка>` рендерит кадры
tools/3d/pack_sprites.py  обрезка кадров и пересчёт meta.json → versions/sprites/barsik
tools/3d/hydrangea.py  гортензия в Blender (`-- carry|gift <папка>`), pack_flower.py упаковывает
tools/app/             Барсик.app: barsik.spec (PyInstaller, universal2), иконка
tests/                 271 тест, запускаются без экрана
COMMANDS.md            справочник команд для пользователя
```

Версия 2 **импортирует** `desktop_assistant as engine`, а не копирует его.
Любая логика работы с файлами живёт только в версии 1; версия 2 — это лицо.
Если правишь поведение, правь в движке, иначе версии разъедутся.

Версия 3 так же наследует у версии 2 мозг (`CatBrain`), окна и `CatApp`, а
подменяет только атрибуты класса: фразы (Барсик — кот, мужской род), скорость
шага, окно, художника и палитру (`Palette` в версии 2: цвета всех окон).
Панель Барсик — «стекло» (`bar_glass`): полупрозрачный только фон-картинка
(`glass_pixels` → PNG → PhotoImage), а не всё окно через `-alpha`, иначе
бледнеют буквы. Размытия под стеклом нет: NSVisualEffectView из Tk недоступен.
Прежняя панель (`PALETTE_PLAIN`, вся через `-alpha`) — переключатель
`wants_glass()`: `--no-glass` > переменная `BARSIK_PANEL` > строка `BARSIK_PANEL`
в `~/.desktop_assistant_ai`. Второй копии файла нет: старая версия сохранена
переключателем, а не копией кода.
Фразы с родом в `PHRASES` — `confused`, `undone`, `bad_command`; если
добавляешь новую, проверь оба рода.

Гортензия есть только у Барсика (`BarsikBrain`): `GiftChance` раз в 90 секунд
безделья поднимает шанс на 5% (в среднем раз в 8 минут), Барсик уходит за край экрана (мимо `clamp`),
возвращается с цветком и отдаёт событие `("gift", (x, y, facing))`; цветок
лежит отдельным окном `FlowerWindow`. Если его позвали работать на полпути,
цветок кладётся там, где он стоит (`_let_go`), — иначе он понёс бы его к файлам.

Скорость ходьбы Барсик не подбирается на глаз: она выводится из `cycle_px` в
meta.json, чтобы опорная лапа не скользила по столу (тест это держит). Если
меняешь шаг в модели (`STRIDE`) или масштаб кадров, перерендери кадры —
`cycle_px` пересчитается сам.

## Инварианты, которые нельзя ломать

1. Трогать можно только пути внутри `ALLOWED_ROOTS` — проверка через
   `is_allowed()`, которая резолвит симлинки. Обходных путей быть не должно.
2. Удаление — только переезд в `TRASH`. Ни `unlink()`, ни `rmtree()` по
   пользовательским файлам.
3. Любая операция сначала показывается пользователю и ждёт подтверждения.
4. Всё, что переехало, попадает в журнал отката (`record_operation`).
5. Файл никогда не перезаписывается: целевое имя проходит через
   `unique_path()`.

Каждый из этих пунктов закрыт тестом. Если тест мешает — почти наверняка
неправ код, а не тест.

## Команды

```bash
python3 -m unittest discover -s tests -t .      # все тесты
python3 -m pyflakes versions/*.py tests/*.py
python3 versions/desktop_cat.py --check                  # диагностика окружения (нужен Mac)
python3 versions/desktop_cat.py --demo                   # показ без трогания файлов
```

Тесты используют только стандартную библиотеку. Зависимостей у проекта нет и
добавлять их не нужно.

## Что чем проверено

**Тесты в любой среде** (в том числе в облачном контейнере): геометрия,
конечный автомат кошки, отрисовка через поддельный canvas (включая проверку,
что ничего не вылезает за окно спрайта), реальные перемещения файлов во
временных папках, многошаговый откат.

**CI на настоящей macOS** (`.github/workflows/tests.yml`, job `window-probe`):
весь набор тестов на Tk 8.6, плюс живая проверка оконных трюков, на которых
держится версия 2. На macos-latest (arm64, Tk 8.6.16) подтверждено:
прозрачность, окно без рамки, «поверх всех», полупрозрачность и что окно
210x170 реально отрисовывается. Там же видно, что при отказе в доступе к
Finder программа корректно деградирует, а не падает.

Там же замерена цена кадра: 300 кадров реального цикла (мозги + отрисовка +
переезд окна) дали медиану ~17 мс при бюджете 40 мс, худшие 5% — ~21 мс.
Запас примерно двукратный. Важно: 17 мс на кадр — это много для шестидесяти
фигур на канве, то есть основная цена, похоже, в переезде самого окна, а не
в рисовании. Если когда-нибудь будет тормозить, смотреть надо туда, а не в
`CatArtist`; запасной план — одно прозрачное окно во весь экран, но оно
перехватывает клики по столу.

Версия 3 там же (шаг «Барсик — кадры, отражение и цена кадра»): все 73 кадра
и их отражения грузятся за ~0.3 с, отражение влево через `copy -subsample
-1 1` совпадает попиксельно, окно 278x224, медиана кадра ~17 мс при бюджете
40 мс, худшие 5% ~18 мс — как у версии 2, картинка вместо фигур не дороже.

**Барсик.app** (`.github/workflows/app.yml`) собирается на macos-latest из
Python с python.org — только он universal2 вместе с Tk, а приложение должно
идти и на M-чипах, и на Intel. Внутри .app Python не видит своих
сертификатов, поэтому движок берёт корневые из macOS (`security
find-certificate`); CI проверяет это `--check` с фиктивным ключом. Ключ ИИ
приложение берёт из `~/.desktop_assistant_ai`: `~/.zshrc` ему не виден.

**Сквозная проверка** `tools/e2e_barsik.py` (job `e2e` в tests.yml, на Маке;
локально — под Xvfb): настоящий Барсик во временной HOME двигает настоящие
файлы — правила, откат, план от поддельного OpenRouter с опасным шагом,
откат, потом гортензия (окно Барсика уходит за край экрана — macOS может не
пустить, это проверяется; цветок ложится окном на экран; щелчок его убирает).
Время ускорено (кадр 1 мс). HOME подменяется до импорта движка.

**По-прежнему требует живого Мака и человеческих глаз:** как это всё
*выглядит* (CI подтверждает, что атрибут принят, а не что кошка красивая),
системные диалоги разрешений TCC, разрешение «Автоматизация → Finder» и
реальные координаты иконок на столе. Замер скорости сделан на виртуалке без
Retina и без настоящего стола под окном — порядок величины, а не гарантия.

Поэтому: **не заявляй, что GUI проверен визуально.** Разделяй «CI на маке
подтвердил, что API работает» и «как это выглядит — никто не видел».

## Стиль

- Комментарии и тексты для пользователя — по-русски.
- Комментарий объясняет «почему», а не «что». Очевидное не комментируем.
- Имена тестов описывают поведение, а не метод: не `test_undo`, а
  `test_two_operations_can_be_undone_one_after_another`.
- Когда чинишь баг — тест, который его фиксирует, обязателен, и в нём
  комментарием что именно ломалось.
